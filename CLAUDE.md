# DB Free — project instructions

Lightweight native database workbench. Rust core (Tauri v2) + React/TypeScript webview.
Follow `/architectural-guardrail`; this file is its translation to this codebase.

## Layers (request path)

```
UI component → src/lib/ipc.ts (client block) → #[tauri::command] (src-tauri/src/commands)
  → guard:: (THE BLOCK, src-tauri/src/guard/mod.rs) → services → store (rusqlite) | integrations (per-DB adapter) → database
```

| Layer | Owns | Never does |
|---|---|---|
| `src/lib/ipc.ts` | the only `invoke`; error normalisation; CommandMap ⇔ CommandName | UI |
| `commands/` | input validation (`ConnectionInput::validate`), call `guard::*`, call one service | touch store / integrations |
| `guard/` | timing, connection+session resolution, read-only lock, destructive confirm, timeout, bounds, history log | feature rules |
| `services/` | orchestrate store + integrations for one use case | import `tauri`, vendor crates |
| `integrations/` | one file per engine implementing `Integration` (postgres, mysql/mariadb, sqlite, clickhouse, redis, mongodb); the only place that engine's crate is imported | know about the UI |
| `store/` | the app's own SQLite (connections, history, buffers); only place `rusqlite` is used for app state | business rules |
| `adapters/` | `aes_gcm` (secret sealing) and `keyring` (master key) | anything else |

## Rules that are enforced (not just written)

- `pnpm check` = `scripts/guardrail.py` + `tsc` + `eslint` + `cargo clippy -D warnings` + `cargo test`. Hand back green.
- Every `.rs` / `.ts(x)` starts with a `SOT:` line. Grep with `grep -rl "SOT:.*<keyword>" src src-tauri/src` before creating anything.
- Every `#[tauri::command]` passes through `guard::local` / `guard::session` / `guard::statement`.
- TS types come from `src/lib/bindings` (generated by `pnpm bindings` from `#[ts(export)]`). Never hand-write a Rust shape in TS.
- No `any`, `as` casts, `@ts-ignore`; `unknown` only inside `src/lib/ipc.ts`. Clippy denies `unwrap`/`expect`/`panic` outside tests.
- UI is HeroUI v3 (`@heroui/react`, compound components, `onPress`) on a black theme. Colours only via HeroUI semantic utilities (`bg-background`, `bg-surface`, `text-foreground`, `text-muted`, `border-border`, `bg-accent`…) plus the app tokens in `src/styles/globals.css` (`text-env-production`, syntax colours). Never a palette class.
- Typed wrappers for HeroUI form controls live in `src/components/global/Field.tsx` (`Field`, `AppSelect`, `Toggle`, `Check`, `Segmented`); use them in features instead of re-deriving `Key` narrowing.
- Secrets: never returned to the UI (`ConnectionSummary.hasSecret` only), sealed with AES-256-GCM, key in the OS keychain.

## Feature map (where each DB Manager-style feature lives)

| Feature | Rust | UI |
|---|---|---|
| Table browser, sort/filter, pager | `services/data.rs`, `integrations/sql.rs` | `features/grid/TableTab.tsx` |
| Inline edit / insert / delete, Pending Changes (review mode), Commit | `services/changes.rs`, `commands/changes.rs` | `features/changes/PendingChangesPanel.tsx`, `DataGrid.tsx` |
| Query tab: run, format, save, AI, explain | `guard/`, `services/ai.rs` | `features/editor/QueryPane.tsx` |
| Saved queries / history | `store/saved_queries.rs`, `store/history.rs` | `features/queries`, `features/history` |
| Export / import | `services/transfer.rs` | `features/transfer/TransferTab.tsx` |
| ER diagram (from FKs) / schema designer | `Integration::foreign_keys`, `ddl` | `features/diagrams/{ErdTab,DesignerTab}.tsx` |
| Dashboards / workflows | `store/documents.rs`, `commands/workflows.rs` | `features/dashboards`, `features/workflows` |
| Redis key viewer | `integrations/redis.rs` | `features/keys/KeyTab.tsx` |
| Settings (incl. AI keys) | `services/settings.rs` | `features/settings/SettingsPage.tsx` |
| Command palette ⌘K | — | `features/palette/CommandPalette.tsx` |

Boundaries with a single audited escape: `src/lib/ipc.ts` (`unknown`), `src/lib/json.ts` (`JSON.parse` any).

## Adding things

- **UI component:** fetch the HeroUI docs first (`.claude/skills/heroui-react/scripts/get_component_docs.mjs <Name>`); v3 API only (no provider, no framer-motion, `value`/`onChange` on Select).
- **Engine (Redis, MongoDB, MySQL…):** follow the numbered recipe at the top of `src-tauri/src/integrations/mod.rs`. Compile errors list every place to touch.
- **Command:** add to `CommandName` (commands/mod.rs) → write the `#[tauri::command]` → register in `lib.rs` → export request type in the `export_bindings` test → `pnpm bindings` → add its signature to `CommandMap` in `src/lib/ipc.ts`.
- **Block concern:** insert a numbered step in `guard/mod.rs`; never a second guard.

## Run

```
pnpm install && pnpm tauri dev      # desktop app (needs Rust toolchain)
pnpm bindings                       # regenerate src/lib/bindings after Rust type changes
pnpm check                          # everything the CI runs
pnpm tauri build                    # .dmg / .msi / .AppImage+.deb for the host OS
```
